# Documentation-vs-implementation audit (2026-07-27) — frontend page numbering fixed, stale doc entries corrected

A full-codebase review comparing every module's actual code against README.md/DataModel.md/Progress.md/Backlog.md/Learnings.md turned up one real, live bug and several stale documentation entries — no other module (metadata schema, orchestration, processing/connectors, dbt, streaming) had any discrepancy.

- **Real bug**: `frontend/pages/4_Streaming_Sources.py` (built 2026-07-18) and `frontend/pages/4_Ingestion_Triggers.py` (built 2026-07-17) both carried the same numeric prefix — a genuine, live filename collision, not a doc error. Streamlit's sidebar ordering between them was alphabetical-by-filename, incidental rather than designed. Fixed by renumbering into one consistent sequence: `4_Ingestion_Triggers.py` keeps its original number; `4_Streaming_Sources.py` → `5_Streaming_Sources.py`; `5_Trigger_Pipeline.py` → `6_Trigger_Pipeline.py`; `6_Model_Table_Columns.py` → `7_Model_Table_Columns.py`. Every reference to the old filenames (tests' `_PAGE_PATH` constants, docstrings, code comments, `created_by` tag string, README.md, DataModel.md, Learnings.md, Backlog.md) updated to match. All renamed/edited Python files confirmed to still compile (`py_compile`) at the time — **runtime-validated in `Progress/2026-07-27-frontend-apptest-coverage.md`**, closing this gap.
- **Stale doc, fixed**: `orchestration/k8s/keda-scaledobjects.yaml`'s header comment described "no cooperative-wake mechanism yet" as a real limitation — the cooperative wake-up mechanism was built and live-verified 2026-07-20 (see `Progress/2026-07-20-cooperative-wake-up.md`). Comment corrected to describe the actual current mechanism.
- **Stale doc, fixed**: `Learnings.md`'s `raw_police_crimes` entry documented the raw file path as `raw/police_crimes/run_id=<id>/crimes.parquet` — the actual current path (post `storage_watermark` refactor, Phase 14) is `raw/police_crimes/<storage_watermark>/police_crimes.parquet`. The underlying fix (raw stays verbatim/unflattened) was never wrong; only the path literal was outdated. Corrected.
- **Stale doc, fixed**: README.md's frontend descriptions (both the top-level folder table and the "What's in each folder" detail) still said "schedules" (the table's pre-2026-07-17 name, before the `ingestion_triggers` generalization) and omitted the Model Table Columns page entirely. Both corrected; `frontend/app.py`'s own in-app sidebar description had the identical omission and was fixed the same way.
